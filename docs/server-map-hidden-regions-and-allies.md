# 隐藏区域与地图 ID 盟友

## 像素隐藏区域

管理员右键地图选择“框选隐藏区域”，使用框选、擦除、移动地图、撤销、恢复、完成和取消工具。边缘对齐底图像素（1 方块）；按住拖拽时显示当前矩形（框选为白色，擦除为红色），保留原选区不变，松开后再合并或擦除。多次笔画合并为一个区域，允许不连通的部分和内部空洞。已有的其他隐藏区域会自动避让。

“编辑隐藏区域”载入原形状继续框选或擦除；完成后仅设置名称与“是否游戏内隐藏”，不再输入矩形坐标。属性窗口内按 Esc 返回绘制，再按 Esc 取消草稿。Ctrl/Cmd+Z 撤销，Ctrl/Cmd+Shift+Z 或 Ctrl/Cmd+Y 恢复。

一次保存只产生一个 ID、一个名称和一个标签。空洞、点击命中、网页地形遮罩、隐藏数据过滤及游戏内地图同步均使用实际像素形状，不使用外接矩形代替。管理员勾选“隐藏区域”时预览透明遮罩；取消勾选不会解除其他玩家的隐藏限制，也不会绕过战争迷雾。

`POST /api/v1/hidden-regions` 示例：

```json
{"name":"L 形区域","hideInGame":true,"rects":[{"minX":0,"minZ":0,"maxX":10,"maxZ":2},{"minX":0,"minZ":2,"maxX":2,"maxZ":10}]}
```

编辑时附加 `id`。`rects` 为整数半开区间，即包含最小边界、不包含最大边界；支持每区域最多 1024 个片段、总计 8192 个片段、256 个区域。服务端合并重叠片段并原子保存，失败不会留下部分区域。GET 同时返回 `rects` 和用于定位的外接边界。

旧的矩形记录与坐标 API 仍可读取；旧记录保持原有包含末端像素的遮罩，编辑时转换为对应像素范围。不会仅因名称相同而自动合并历史记录。新形状需要新版客户端与服务端模组；旧版只认识外接矩形，不能正确编辑新形状。

## 地图 ID 盟友

登录后点击工具条的盟友按钮，在搜索框下方输入对方的玩家地图唯一 ID，点击“申请”。面板显示自己的可复制 ID，以及盟友或待处理申请的 2D 头像和名称。收到申请时，列表操作按钮显示“允许”；自己发出的申请显示无操作的“等待”，对方允许后才变成“删除”。

地图 ID 按世界持久保存，独立于游戏 UID、玩家名称、密码和网页会话。请只向希望共享探索的玩家提供自己的 ID。申请不会直接建立共享关系，必须由对方点击“允许”；删除则解除双方关系。申请最长保留 10 分钟，过期会自动清除。无游戏同阵营记录、自己没有探索记录或对方离线时同样有效。服务器关闭共享时不能申请或允许，但仍可删除。

`GET /api/v1/allies` 返回 `{enabled,mapId,members:[{uid,name,online,avatar,pending,pendingUntil}]}`；`pending` 为 `incoming` 时可允许，为 `outgoing` 时表示等待；已建立关系为 `null`。匿名响应没有 ID 或成员数据。

- 申请：`POST /api/v1/allies`，`{"action":"add","mapId":"对方的地图ID"}`。
- 允许：`POST /api/v1/allies`，`{"action":"accept","uid":"申请者的uid"}`。
- 删除：`POST /api/v1/allies`，`{"action":"remove","uid":"成员列表返回的uid"}`。
- 写入必须登录并携带 `X-ServerMap-Request: 1`。禁止申请自己、重复申请和未知 ID，双方各最多 64 位盟友。
- 已接受的旧盟友关系保留；旧待处理邀请不会自动变成已加入关系。
- 加入或删除后发送可见性更新，刷新地形、迷雾及相关私有标记。

## 战争迷雾总开关与区域标记

管理员在“管理 → 战争迷雾”中使用“启用战争迷雾”总开关，保存后实时刷新地图。旧配置默认开启；关闭时所有访问者的底图和公共地图标记不再受探索限制，但隐藏区域、私人数据和玩家位置权限不变。探索记录持续保存，重新开启不会丢失已有探索；“管理员无视战争迷雾”和探索共享的配置独立保留。

开启迷雾时，区域标记的填充只包含自己或允许共享的玩家探索过的 32×32 格网。文字在已探索形状的内部重新排布并裁切；边框仅保留原始区域边界中已探索的线段，不在迷雾切口新增边框。完全未探索的标记不向普通用户返回。

`GET /api/v1/area-markers` 的 `rects` 是显示范围；迷雾裁剪时 `borders` 是可见原边界的 `[x1,z1,x2,z2]` 线段，空数组表示没有可见边界。管理员额外取得 `editRects` 原稿，进入编辑、避让、合并和保存均使用原稿，不会误删未探索部分。`GET /api/v1/fog/regions` 返回 `enabled` 总开关状态。

## 原生地图探索同步

### 当前世界的完整历史地图（ServerMap 0.3.9）

进入游戏并完成双端能力和世界 ID 协商后，客户端从当前 `ChunkMapLayer` 已打开的 `MapDB` 获取唯一缓存文件；不会遍历其他存档的 `Maps/*.db`。后台使用独立只读 SQLite 连接，按原生 27 位 X／27 位 Z 的键分页读取 `mappiece`，只导入可解码为 32×32 像素的有效图块。无需移动玩家或逐处拖动游戏地图，也不上传图片、不修改游戏缓存。

- 每批最多 256 个坐标、间隔 500 ms；后台仅缓冲两页，读取期间释放每页的数据库读取锁，不会等待网络确认时长期锁住游戏缓存。丢失确认时每 2 秒重发同一批。
- 历史同步不受原生增量队列的 65536 区块容量限制；每次完整快照最多 200 万个区块。超限或读盘失败会明确记录错误，不会静默截断或应用半份结果。
- 服务端按连接、玩家、世界 ID、快照 ID、顺序、维度、坐标边界及频率校验。中间确认只表示分批数据已缓冲，只有完整读盘、全部分批送达并持久化成功后才确认完成、准确替换该玩家的个人探索范围。
- 完整替换会收回旧算法多开的区块；其他玩家记录、盟友关系、原生地图缓存和存档不变。扫描期间已确认的新生成区块会并入快照，之后继续增量同步。断线、中断、读盘或保存失败不清空旧记录；重新进入游戏会重新完整同步。
- 替换使范围减少时发送 `visibility`，刷新本人和盟友的底图、标记并使旧传送确认失效；纯增加仍使用 `exploration`，不会打断有效编辑或传送确认。盟友共享、管理员豁免和隐藏区域规则继续独立生效，网页实际地形仍由服务端渲染。

历史缓存是明确接受的客户端可信来源，可能被复制或修改，无法用本次连接的区块发送记录证明其全部历史真实性。世界 ID 校验用于防止误串世界，不等于防篡改认证。缓存中的有效探索会用于迷雾和传送权限；管理员隐藏区域等服务端限制仍保留。旧客户端／旧服务端没有完整历史同步能力时，只保留原有增量同步并提示升级。

### 后续原生生成增量

新增探索来自客户端原生 `ChunkMapLayer.GenerateChunkImage()` 的成功结果。该方法只有在 32×32 区块列的所有纵向区块都已从服务器加载后才返回图块；返回 `null`、仅请求区块、移动玩家、调整视距、拖动地图到未知范围均不会直接解锁网页地图。不再使用固定的 9×9 区块窗口。游戏实际生成的离散区块按原坐标记录，不填充外接矩形或周围区块；地图窗口、缩放和游戏的分批加载自然决定新增形状。

- 原生后台生成线程只入队，主线程每 500 ms 最多发送 256 个去重坐标；未收到确认时每 2 秒重发同一批次。原生重绘不会反复上传已确认图块。
- 服务端核对该连接实际完整发送过的纵向区块列，不使用服务器全局已生成区块、玩家坐标或视距推测。保留最近 65536 个完整列的发送证明，允许快速移动/传送卸载后的延迟上报；仍在游戏发送集合中的完整列也可实时核验。
- 协议绑定连接随机令牌和批次序号，只支持主世界并检查世界边界、批量上限、频率和重放。不能拿其他玩家、其他维度或旧连接的发送记录授权新探索。只有持久化成功才确认，保存失败不启用内存中的迷雾/传送权限，并允许重试。
- 客户端待发与已确认去重缓存各有 65536 个区块上限；极端积压溢出会记录警告，不会用半径补开迷雾，未入队部分需原生重绘后再次同步。
- 新增探索通过不含玩家身份/坐标的 `exploration` 事件通知网页，合并刷新底图、迷雾与标记；不会取消当前区域编辑或有效传送确认。阵营变更等可能撤销权限的通知仍走 `visibility` 流程。

客户端和服务端都需要新版模组；原生生成挂钩失败时不启用猜测半径的回退。网页热重载不能代替游戏模组重载。0.3.5 的纯增量同步不会导入历史缓存；0.3.6 起按上述完整快照流程校正个人探索。

## 验证

`scripts/test-map-fog-navigation.cjs` 使用 4096 个地图区域的模拟数据，对比普通玩家、管理员绕过及匿名用户的缩放拖拽。网页直接显示服务端已遮蔽的瓦片，导航时不再请求 `/fog/regions`、展开覆盖区块或创建透明矩形；仍验证新增探索、可见性变更、退出登录和迷雾开关会重新加载底图。可设置 `MAP_TEST_INDEX` 与 `MAP_FOG_PROFILE_ONLY=1` 使用旧页面对比主线程长任务。

`MapHistorySyncTests` 覆盖超过 65536 个区块的完整传输、分批确认、重试、取消、快照中断／替换、错误世界和失败最终保存。`MapTeleport/MapHistoryChecks.cs` 使用真实原生 `MapDB` 创建缓存，验证只读分页、原生坐标编码、坏数据过滤、并发写入、自动客户端上传及真实服务端的原子替换／回滚。`test-map-fog-areas.cjs` 同时验证完整替换后本人和盟友的旧范围与区域标记自动收回。

`MapExplorationSyncTests` 覆盖同步队列、重试、批次和授权边界；`scripts/test-fixtures/MapTeleport` 还直接调用本机游戏的原生生成方法和 `ConnectedClient.SetChunkSent()`，验证真实 Harmony 挂钩、整列检查、保存失败回滚和重连隔离。`test-map-fog-areas.cjs` 验证浏览器不移动时的单区块增量、邻格保持迷雾、盟友刷新及编辑草稿保留；`test-map-teleport-ui.cjs` 验证新增探索不会取消传送确认。

`MapNotebookTests`、`AllianceTests` 覆盖持久化、兼容、像素边界、空洞、快照隔离、传送快照比较、失败原子性及加入权限。`scripts/test-map-hidden-regions.cjs` 配合隔离服务器夹具验证真实 HTTP、地图 Host 转发、桌面鼠标、手机触控及盟友面板；设置 `PLAYWRIGHT_MODULE` 指向本地 Playwright 安装，使用 `test-map-notebook-api.ps1 -TestScript test-map-hidden-regions.cjs`（可加 `-ThroughHost`）。不向运行中的网站同步网页文件。

`AreaMarkerVisibilityTests` 和 `MapManagementTests` 验证裁剪、原边界、空洞、负坐标、大范围、随机像素对照及总开关持久化。`test-map-notebook-api.ps1 -TestScript test-map-fog-areas.cjs` 使用真实 HTTP 与桌面/手机浏览器验证开启/关闭、匿名访问、管理员例外、盟友共享、文字位置、实时设置事件、旧响应竞态及原稿编辑。
