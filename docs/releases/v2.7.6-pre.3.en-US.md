# LauncherGo 2.7.6-pre.3

## Added

- The bridge mod records an initial online player count at startup, then records the UTC timestamp and count only when the count changes. It provides the `player.count-changed` event and `players.history` query.
- Bridge player history is persisted as `launchergoserverbridge-player-history.json` in the mod configuration directory with seven-day retention. The Open API subscribes to count changes and keeps a local history cache in each profile directory.
- The Open API prefers bridge `server.status` data for the server name, description, version, online player count, and uptime. Responses add `serverStatus`, `worldName`, `address`, and `maxPlayers`; local status and configuration provide a fallback when the bridge is unavailable.

## Improved

- Removed five-minute Open API sampling. `/api`, `/api/server`, and `/api/players/history` use bridge player history.
- Added a one-second bridge status cache and a five-second history query cache per profile to reduce repeated queries.
- Bridge history writes are batched with a 250-millisecond delay and saved in the background to reduce synchronous disk work during player joins and departures.

## Notes

- Launcher **2.7.6-pre.3**; the embedded bridge mod is upgraded to **2.2.0**. Restart the game server after deployment to load the updated mod.
- The API returns `playerCountHistoryMode: "on-change"` and `playerCountHistoryHours: 168`, and removes `playerCountIntervalMinutes` and `playerCountHistoryPoints`. Clients should use each record's timestamp to handle irregular intervals.
- An abrupt game server exit can lose recent count changes that have not yet been written to disk.
