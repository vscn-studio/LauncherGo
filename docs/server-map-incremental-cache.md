# ServerMap 增量缓存

地图模组随游戏服务器运行。首次安装或升级会在后台发现存档区域、提取地表并生成地图，已有图片继续提供服务。完整缓存建立后，正常重启恢复任务日志和区域索引；检查派生文件的完整性，但不枚举世界存档、不提取地表，也不重写有效的父瓦片。

## 更新入口

- 已有完整缓存的区块加载不会安排重绘。新生成、标记为变化的区块，以及缺少缓存或此前尚未生成完成、现在已完成的柱，先写入待保存日志。
- 1.22.x 保存适配器在实际保存方法开始时冻结变化世代，观察同步或区块线程保存成功后，在游戏 tick 中提交任务。没有一秒延时假设。保存失败、超时、无法安装适配器时不确认变化已经保存。
- 提取过程中再次保存会使本柱的读取失效并重试；后来的变化不会被前一世代确认清除。存档外围的预生成柱可能长期未达到 `Done`，它们保留旧内容并记录为“地形生成未完成”。普通保存不会反复安排这些柱；探索触发生成完成后再更新。此状态与保存失败、尚未保存的真实变化分别统计。
- 月份或有效色表变化只安排彩色地图任务。色表版本对有效条目按方块代码排序、屏蔽无效 alpha 后计算摘要；等价上传不会重绘。缺少色表时仍建立地表和无颜色地图，彩色任务等待管理员客户端上传。
- HTTP 地图浏览和进度查询不会创建或提升渲染任务。

## 手动重建

启动器地图配置页的“重建缓存”在“重置网页”右侧、“打开地图”左侧，通过当前档案的服务器命令通道发送：

```text
/servermap cache rebuild
```

仅服务器控制台或游戏 root 管理员可以执行。命令立即提交后台工作；重复提交被拒绝，停服或模组不可用时启动器禁用按钮。重建请求、扫描游标及未完成任务跨重启保留。更新以原子替换方式进行，不删除存档、账号、地点标记、轨迹、隐藏区域、自定义网页或头像。

`/servermap render all` 从地表缓存重绘两类地图；`cache rebuild` 另外重新核对区域集合、提取地表并重建传送器索引。离线编辑存档、恢复备份或停用地图模组期间修改世界后，应执行 `cache rebuild`。

## 持久化与调度

每个世界的 `ServerMap/<世界ID>/` 包含：

| 文件 | 内容 |
| --- | --- |
| `cache-state.db` | 独立 SQLite WAL 日志：区域、扫描进度、待保存世代、目标任务、父节点任务、正常关闭标记 |
| `surface/<x>_<z>.br` | Brotli 地表快照，包含高度、有效像素、稳定方块代码、材质键、无颜色属性和柱指纹 |
| `surface/<x>_<z>/<柱序号>.br` | 尚未合入区域文件的柱快照；先原子写入，再确认该柱工作完成 |
| `2d/…/*.surface` / `*.colors` | 地表内容版本、独立图片算法版本和色表版本 |
| `2d/…/*.sha256` / `*.children` | 图片完整性摘要、父图片所依赖的子图片版本 |

缓存数据库由单写入者批量事务写入。停服只等待日志提交，不等待地图工作完成。损坏的状态数据库会保留为 `.damaged-*`，重建其索引；异常退出执行恢复核对，用保存内容指纹复用可确认的地表。局部地表/图片损坏只安排相关修复。

提取、着色、传送器索引和父瓦片共享 `RenderThreads` 工作线程。一个提取工作单元处理一个柱，完成后让出调度。优先级为已保存变化及父瓦片、建立/重建缓存、季节着色；连续八个高优先级单元后允许一个后台单元。相同目标合并，运行中的相同版本不会重跑。父节点按目标依赖版本去重并保留未完成状态。

传送器首次索引后，只读取变化柱中记录的变化区块；不存在的保存记录会清除旧索引，不永久重试。读取异常进入有限退避，并在进度中报告；已确认内容保留。

## 进度与验证

`api/v1/render-progress` 保留原有字段，增加 `cacheProtocol`、`reason`、`rebuilding`、`rebuildId`、`pending`、`surfaceExtraction`、`cacheReused`、`coloring`、`parents`、`indexing`、`mapColumnReads`、`chunkReads`、`chunkDeserializations`、`waitingSaveTasks`、`merged` 和 `error`。统计为当前进程累计值；持久化的剩余任务和重建状态不会因重启丢失。日志包含扫描原因、游标、读取/复用计数和耗时。

`surfaceExtraction` 和 `indexing` 的单位是已处理的区块柱；同一柱因后续变化再次处理时会继续累计。`indexing` 不是传送器数量。`coloring`、`parents` 是累计写入的图片数。`translocatorCount` 单独提供实际索引端点数量；`awaitingSave` 是尚未确认保存的柱数，`deferredGeneration` 是待后续探索生成的柱数。排队和处理中为零，与这些累计值大于零并不矛盾。

`dotnet watch run` 启动构建使用 Debug 输出，启动档案时 LauncherGo 部署内置 ZIP；游戏服务器及客户端进程已加载的程序集不会跟随 LauncherGo 热重载。确认实际代码时应核对启动日志中的程序集构建标识与 ZIP 内的 `ServerMap.dll`，不能用 Debug/Release ZIP 压缩包哈希差异判断版本。服务器与客户端更新后均需重新启动对应游戏进程。

原版散落石头和石堆（`BlockLooseRock`）按自身材质取色。游戏的位置版取色函数会读取脚下方块；色表生成位置并不是真实石堆位置，不能调用该重载。旧的扩展色表若已含这些方块的材质样本，加载时自动修正有效颜色摘要，只重新着色彩色地图；木柴、锭堆和 GroundStorage 继续按容器内实际物品取色。

框选截图直接读取服务端第 0 层原始瓦片，按当前可见图层叠加标注并输出 PNG。Leaflet 的原始级别 `nativeZoom` 对应服务端级别 0。截图测试会解码 PNG 核对像素、缩放坐标和图层开关；仅 HTTP 200 不代表存在地形，因为未知或隐藏区域可以返回透明占位图。全部选区均无地形时提示重新选择，部分缺失保持透明；不会用网页背景掩盖缺图。

自动验证包含：SQLite 日志恢复/损坏、世代合并、柱缓存往返与局部合并、档案端口及令牌路由；游戏程序集夹具验证保存适配器挂接、慢保存/失败、色表规范化、运行期方块编号重分配后的缓存着色、父瓦片复用/损坏修复、队列去重和八比一调度；已有屋顶、堆叠物品和网页桌面/手机回归测试继续覆盖相关行为。

实际长期运行中的世界生成、作物生长和第三方模组事件仍需真实服务器运行验证。保存适配器依赖 1.22.x 的保存方法与同步锁；游戏改变内部布局时应重新适配，而不是退回固定时间等待。
