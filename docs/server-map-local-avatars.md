# 本地地图头像

服务器请求玩家客户端当前角色的头部网格和所用贴图片段，在本地生成 256×256 PNG 头像，无需外部头像服务或手动准备图层。

头像沿原生模型负 X 轴正面取景，不附加侧转或俯仰；渲染版本变化会使旧头像缓存失效，下次客户端回传后生成新图。

## 默认流程

- 服务器与玩家客户端都安装新版 ServerMap。进入游戏后自动同步，普通玩家无需管理员权限。
- 客户端在原生角色网格生成完成、第一人称裁剪之前，按头部及子骨骼提取头部，保留发型、胡须和头部穿戴；同时支持角色、物品和方块贴图图集。只回传头部三角形和所用 RGBA 片段，不上传整张图集，也不重新生成角色模型。
- 服务器按请求令牌、连接玩家、超时及大小限制接收分片，在单后台任务中生成头像；网页下次玩家刷新时自动显示。
- 缓存位于 `ServerMap/<世界ID>/client-avatars`。重连先复用缓存，再后台刷新一次，以适配客户端资源包变化；外观改变也会触发更新。
- 新玩家首次同步完成前显示默认图标。旧客户端或没有标准 `Head` 节点的自定义模型可能无法提供头像，失败原因记录在客户端日志。

正常日志包含 `head mesh snapshot ready`、`head model and cropped textures queued`（客户端）和 `Client-model avatar generated and cached`（服务器）。网页默认头像的悬停提示区分等待客户端、等待模型、传输、生成、重试和图片加载失败。

## 可选：预渲染图层

仍支持在实例 `ServerMap/servermap.json` 中设置 `AvatarAssetsPath` 作为备用图层目录。支持直接指向包含 `baseskin` 的目录，也支持其上层的 `v2` 或 `public/v2` 布局。留空时尝试 `ServerMap/<世界ID>/avatar-layers`；目录不存在不影响默认客户端模型头像。

例如：

```json
{
  "AvatarAssetsPath": "D:\\AvatarLayers"
}
```

修改备用图层配置或素材后重启游戏服务器。LauncherGo 写入其他地图配置时会保留此字段。

## 图层格式

所有图片必须是 256×256 PNG，单文件不超过 1 MiB。推荐使用透明背景。

```text
baseskin/<皮肤代码>.png
eyecolor/<眼睛代码>.png
hairbase/<发型代码>/<发色代码>.png
hairextra/<附加头发代码>/<发色代码>.png
mustache/<胡须代码>/<发色代码>.png
beard/<络腮胡代码>/<发色代码>.png
```

每个图层所在目录可选放置 `mask.png`：黑色不覆盖，白色覆盖，灰色及透明度控制部分覆盖。没有 mask 时使用 PNG 自身透明度。除皮肤和眼睛外，代码为 `none` 的部件跳过。所选部件素材缺失时不输出错误的半成品头像，而是使用默认图标并记录缺失文件。

## 缓存与性能

- 客户端模型传输采用 48 KiB 分片，每 200ms 最多发送两片；每次请求最多 3 MiB，解压后也有限制。只接受服务器发起且属于发送玩家的请求，最多同时接收 8 个头像，失败后限速重试。
- 头像渲染有顶点、贴图像素和逐像素工作量上限，文件写入不会占用游戏线程。
- 以下参数适用于可选的预渲染图层模式：
- 读取游戏 `skinConfig/appliedParts` 的七个外观字段，不读取账号头像、不请求外部服务。
- 单后台任务生成，同一外观的并发请求合并；地图请求不等待合成，后续玩家刷新会带上完成的头像。
- 头像写入 `ServerMap/<世界ID>/avatars`，使用外观与素材版本的 SHA-256 标识，本地 HTTP 提供 PNG。浏览器可缓存一天。
- 每次服务器运行最多登记 512 套外观，缺失素材的失败请求一分钟内不重复生成。重启可复用已有磁盘缓存；素材的路径、大小或修改时间变化会生成新的版本标识。
- 停服时取消排队任务。磁盘缓存不自动删除，以免误删部署数据；维护者可在停服后自行清理旧缓存。

## 验证状态

测试覆盖模型格式、传输归属/重放/超时、解压限制、软件渲染、缓存及游戏服务器 HTTP 接口；另有隐藏 OpenGL 窗口测试实际贴图裁切、RGBA 顺序和图形状态恢复。真实玩家外观及联机显示仍需客户端实测。
