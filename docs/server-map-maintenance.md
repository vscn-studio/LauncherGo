# 地图网页与模组独立维护

地图由三部分组成：游戏内 `servermap.zip` 提供数据和游戏操作；独立的 ServerMap Host 提供网页、代理 API 和注入网站配置；WebRoot 包含 HTML、JS、CSS 等静态资源。纯网页改动不需要重新部署游戏模组。

## 地图配置页

顶部地图操作依次为：**部署地图模组、启动／停止地图、重置网页、重建缓存、打开地图**。通用的返回、保存、刷新仍保留；窗口变窄时按钮换行。自定义 WebRoot 旁只保留目录选择，不再提供第二个“更新网页”入口。

- **部署地图模组**：唯一会安装或替换地图模组的入口。仅影响所选服务器档案的 Mods，不修改客户端。确认框展示目标和版本，游戏服务器运行时提示下次手动重启生效。内容相同不重写；替换前备份至档案的 `ServerMap/Backups/<时间>-mod-<唯一编号>/servermap.zip`。确认后文件发生变化会中止，避免覆盖新的手工改动。按 `modid` 检测 ZIP／目录形式的重复安装；非标准名称、目录包、占用标准文件名的其他模组或链接路径需要用户先处理。
- **启动／停止地图**：只控制 Host，不再自动部署模组，首次缺失也不安装。缺少模组会显示警告；Host 可独立运行，但游戏数据可能不可用。已有不同版本不会强制升级或降级。
- **重置网页**：使用本机当前 LauncherGo 内置网页，不联网下载。只使用已保存配置；有未保存修改时需先保存。同名 HTML／JS／CSS 会被备份并覆盖，包括手工编辑的文件；目标独有文件保留。默认目录在 Host 运行时立即更新，停止时在下次启动应用。自定义目录在停止时也可以重置；若已保存目录与运行中的目录不同，需要手动重启 Host 切换。网页静态资源附带内容版本号，刷新浏览器后加载新版本。
- **重建缓存**：保留现有 `/servermap cache rebuild` 命令和后台进度；不直接删除目录，不更新模组。服务器、命令通道或缓存协议不可用时显示原因。
- **打开地图**：只打开浏览器，不附带启动、安装或升级操作。

网页重置不会清除公告、自定义 JS／CSS 配置、玩家 localStorage 设置、地图数据、战争迷雾或瓦片缓存。备份放在网页目录外的 `ServerMap/Backups/<时间>-web-<唯一编号>`；如果自定义 WebRoot 包含此备份目录，操作会被拒绝，需选用独立网页目录。

网页更新按文件原子替换，首页最后更新；并非整站事务。失败时不会报告成功，会显示备份路径；释放占用后可重试，或手动恢复备份中的文件。不会自动删除备份。部署／重置／启停执行期间禁用冲突操作和档案切换。

## 如何单独更新

1. 普通维护：更新 LauncherGo 后点击“重置网页”，无须点击“部署地图模组”，通常只需浏览器刷新。
2. 独立静态网页：将完整 WebRoot（包括 vendor、assets 和许可证）放入自定义网页目录并保存；首次切换目录手动重启 Host，以后替换目录内网页即可。独立包应更新资源版本参数；需要恢复软件内置网页时再使用“重置网页”。
3. Host 程序更新：手动停止、启动地图网页服务以加载新程序，不需要重启游戏服务器。
4. 涉及新后端数据或游戏行为：明确部署对应地图模组，并在合适时间手动重启游戏服务器。网页更新不能补齐旧模组没有的 API，也不能修复旧 Host 自身的注入逻辑。

本次不提供在线网页更新源、不增加游戏 HTTP API，也不自动迁移或替换已安装的模组。
