# 地图坐骑斜上方缩略图

ServerMap 0.3.3（主程序 2.7.1-pre.3，版本号不变）增加右侧“坐骑”图层，默认勾选，按服务器地址保存勾选状态。它显示从游戏实际模型、贴图生成的透明静态斜上方图，不是坐骑图标，也不会用图标占位。

## 显示规则

- 只显示在线玩家当前乘坐的可控制实体，乘客席也计入；同一载具按实体 ID 合并，只显示一次。下马、离开座位或断线后，下一轮刷新移除。单纯站在飞艇甲板上不计为骑乘。
- 使用坐骑自身的位置、朝向、模型尺寸和中心偏移，不使用玩家的视线方向。小型模型水平最长边 ≤4 格时放大 2 倍，≥8 格保持 1 倍，中间线性过渡；随后随地图等比例缩放，不设置 28～36px 等固定最小尺寸。尺寸判定取采集时零朝向的物理包围盒，不随转向或地图缩放改变。
- 摄像机偏离正上方 25°，预渲染 16 个方向（22.5°一档），相机和地图光照固定；转向切换模型帧，不使用 CSS 旋转斜视图片。所有方向共享一个投影尺度与实体原点锚点，避免大小跳动；有分档转向，不做交叉淡入造成重影。
- 图像位于地形和玩家标记之间，按已裁切的透明轮廓添加轻微向下的柔和阴影，不给图集相邻帧投影；无背景矩形、外圈、行走动画、水面摇摆动画；头像、名称等仍由原有“玩家”图层控制。关闭“玩家”不会关闭“坐骑”。
- 权限沿用玩家坐标规则：需要登录，普通玩家只看自己的骑乘实体，管理员可看所有在线玩家的骑乘实体；`PublicPlayers=false` 时不展示。不会额外公开同车乘客的账号或名字。
- 非管理员无法获取与隐藏区域相交的整个模型图像，即使实体原点位于区域外。图片接口每次检查骑乘快照、权限、图片键和放大后的整张图集共同投影包围盒（覆盖全部方向），并返回 `no-store`。已下载的数据无法撤回。

## 升级与兼容

服务器、网页和参与采集的骑乘客户端均需更新本次 ServerMap 构建。虽然显示版本仍为 0.3.3，旧构建不能产生新的方向图集；网络通道已隔离升级至 v2，旧单张俯视图不会被误当成图集。自定义 WebRoot 需包含新的 `mounts.js`。不需要删除存档、瓦片或地点数据。客户端原有安装方式与模型头像采集相同，不增加额外模型资源包。

通过游戏标准 `MountedOn` / `IMountableSeat` / `IMountable` 识别坐骑，复用 `EntityShapeRenderer` 的实际网格及实体、物品、方块纹理图集。原版马鹿、木筏、船和 Team-Airship/VSAirshipmod 的座席及主体渲染器符合这条接入路径，无需把名称写死，也无需强制依赖飞艇模组。

动物坐骑（`EntityAgent`）使用隔离的骨骼副本计算固定 `idle` 站姿第 0 帧，包含原生网格中已经合成的鞍具等附件；不再把行走、奔跑、跳跃、游泳中的收腿姿态固定进缩略图。没有已知站姿动画时回退模型原始绑定姿态，不回退实时运动帧。船和飞艇仍保留采集时的结构状态，不套用动物站姿。

隔离计算不停止或推进游戏动画，不触发动画声音/事件，不修改实时姿态、原始关键帧、骨骼编号及共享缓存。其他渲染器单独绘制的特效、附件或自定义动态几何仍不保证包含。首次需要同一坐骑上至少一位玩家安装新版客户端模组，完成采集前不显示该模型。失败时留空并重试，不替换为通用图标。

站姿修复需要更新骑乘客户端的 ServerMap 构建（显示版本仍为 0.3.3）。已生成的旧图片在下一次成功采集后替换，正常刷新周期约 120 秒；只刷新网页不会立即重新生成模型。服务端重启会清除内存图像缓存，无需删除地图或存档。

游戏模型、贴图及衍生俯视图的相关权利归游戏及对应模组、资源包作者。原始素材仅在客户端运行时读取，不随本项目或模组 ZIP 分发。

## 技术约定与资源限制

- 专用网络通道：`servermap-mounted-model-v2`，不改变旧头像通道协议。服务器每秒发布骑乘快照；网页可见时桌面约每 2 秒、手机约每 5 秒刷新，拖动或后台标签页暂停请求。
- 在客户端图形线程复制当前坐骑原生网格、读取所用贴图片段；保留并执行原始上传回调，不修改游戏网格或动画状态。在后台先按 16 个 yaw 旋转真实三维顶点，再用固定的斜视摄像机投影、深度遮挡与世界光源着色。每帧 256×256，按 4×4 排列为 1024×1024 透明 PNG。网页用裁切窗口选取最近方向（负角度和 0°/360°回绕均归一化），切换不重新下载。大型模型未放大前的 1 方块在原生地图缩放下约等于 1 CSS 像素，斜视深度轴会有正常的缩短。
- 每次最多 72,000 个三角形顶点、2 Mi 像素贴图、128,000,000 次（整个 16 帧图集共用）栅格包围盒像素预算；PNG 图集最多 4 MiB。只发送最终 PNG 图集、物理最长边、投影尺寸和中心偏移，不上传完整模型文件或整张纹理图集。
- 服务器只接收向当前乘客主动请求的随机令牌上传，分块 48 KiB，验证所有权、顺序、尺寸和超时，最多 4 份并行传输、1 个解码任务。强制检查 PNG 尺寸并重新编码，丢弃客户端元数据。
- 服务端图片仅保存在内存，最多 32 份或 32 MiB（每张解码后 4 MiB，限制方向图集带来的内存开销）。成功图像约 120 秒允许重新采集，失败约 60 秒重试；移动和转向仅更新坐标、当前图集帧，不重建图片 DOM 或重新下载相同图像。下马后缓存可能暂留，但接口不再允许访问。

## 验证

- `scripts/test-fixtures/MountPose`：读取本机游戏实际马鹿模型，验证行走、快步、奔跑、跳跃、游泳共 20 个动画阶段都输出与游戏 `idle` 一致的固定站姿，前肢无运动屈曲；检查头部站姿与附加装备骨骼、实时帧/姿态/逆绑定缓存/关键帧不变，以及载具状态保留和缺少站姿的回退。
- `MountMapTests`：16 方向投影、侧面显露、转向遮挡、固定光源、透明面、大小放大规则、共同尺度与偏移、资源预算、取消、上传所有权/顺序/过期、下马期间丢弃结果、放大后图集包围盒权限。
- `scripts/test-map-mounts.cjs`：实际 Leaflet 桌面/手机模拟，小型 2 倍/大型 1 倍、16 方向切帧、回绕、锚点与尺度稳定、移动复用、开关独立及刷新持久化、下马移除、无占位图、PNG 导出方向及轮廓阴影。测试图片为合成几何，不是游戏素材。
- `scripts/test-map-mounts-api.cjs`：由 `test-map-notebook-api.ps1 -ThroughHost` 调用，在隔离游戏服务器内验证真实 PNG 解码及 HTTP 权限链路，不影响日常存档。
- 已通过编译、上述测试以及头像、地点图片、传送器回归。未在运行中的游戏客户端现场验证马鹿、船和飞艇的完整外观；上线前需实际骑乘检查贴图、附件、16 方向切换、模型相对地面的高度偏移、下马移除及客户端帧率。协议/接口测试不替代实机渲染验证。
